# v0.2.0 — candidato experimental, no publicado

OpenAPI Contract Lab compara dos contratos locales con **oasdiff 1.39.0** y añade explicaciones deterministas para revisión humana. El [issue #33](https://github.com/v1kz25/openapi-contract-lab/issues/33) prepara estos bytes para revisión. No se ha creado tag ni release, tampoco draft. Cualquier fusión o publicación requiere aprobación explícita posterior.

## Alcance respecto a v0.1.0

- **Trece explicaciones** verificadas, conservando las diez originales. Nuevas combinaciones de nivel 3: `request-parameter-type-changed`, `request-body-became-required` y `response-required-property-removed`. Otros motores, versiones, reglas o niveles conservan fallback neutral.
- **HTML y Markdown agrupados** por pares exactos ruta/método, con resumen por grupo, índice HTML y severidades `error`, `warning`, `info`, después desconocidas. Sección final para hallazgos sin ruta u operación. Orden upstream dentro de cada severidad y numeración original; sin pérdidas ni deduplicación.
- **Regresión acotada OpenAPI 3.1.0**: cinco comparaciones de idéntico, descripción, obligatoriedad, unión con null y propiedad de respuesta, con exportaciones JSON/HTML/Markdown. Son casos concretos, no compatibilidad completa.
- **Identificación v0.2.0** en CLI/tests/smoke y cabecera de avisos. La estabilización del runner de investigación corrige únicamente la base usada para su directorio de salida relativo.

Se conservan el evento upstream y todos los campos/orden del JSON, política de severidad, códigos 0/1/2/3 y protección de archivos. No se añaden nuevas reglas, dependencias ni funcionalidades durante la preparación del candidato.

El spike #25 investigó `diff`/`summary`/`changelog`: **no está implementada** una clasificación de contratos idénticos, cambios solo documentales o contractuales. SARIF, GUI, distribución multiplataforma y soporte verificado de OpenAPI 3.2 siguen fuera.

## Paquete para revisión

Archivos de candidato: `openapi-contract-lab_0.2.0_windows_amd64.zip` y `SHA256SUMS.txt`. Son artefactos locales de revisión, no archivos de una release publicada. Comprobar el SHA-256 del ZIP antes de extraer en una carpeta nueva. Los checksums identifican bytes, no constituyen una firma digital.

El ZIP contiene nuestra CLI, ejemplos sintéticos 3.0.3/3.1.0, ejemplos de informes agrupados, estas notas, LICENSE, NOTICE, THIRD_PARTY_NOTICES y BUILD.txt. Este último identifica el SHA fuente, herramientas, flags y hash del ejecutable. **No incluye oasdiff, SDK, cachés ni informes con rutas privadas.**

Solo **Windows x64** verificado, PowerShell 5.1 y 7. Go **1.27.4** se necesita para compilar desde fuente, no para ejecutar el ZIP. Para comparar, obtener **oasdiff 1.39.0** por separado desde su [release oficial](https://github.com/oasdiff/oasdiff/releases/tag/v1.39.0). La [guía de candidato](https://github.com/v1kz25/openapi-contract-lab/blob/release/0.2.0/docs/CANDIDATE-V0.2.0.md) fija compilación y comprobaciones. Coste adicional obligatorio **0 €**, sin APIs de IA ni servicios remotos.

## Uso desde el ZIP extraído

```powershell
.\openapi-contract-lab.exe --version
# openapi-contract-lab v0.2.0
$motor = 'C:\tools\oasdiff-1.39.0\oasdiff.exe' # ejemplo: adaptar a la ubicación local
.\openapi-contract-lab.exe compare --oasdiff $motor .\examples\base.yaml .\examples\required.yaml
$LASTEXITCODE # 3: informe completo; breaking con política predeterminada
.\openapi-contract-lab.exe compare --oasdiff $motor .\examples\required.yaml .\examples\base.yaml
$LASTEXITCODE # 0: compatible
$salida = '.\revision-' + [guid]::NewGuid().ToString('N') + '.html'
.\openapi-contract-lab.exe compare --oasdiff $motor --format html --output $salida .\examples\openapi31\base.json .\examples\openapi31\union-null.json
$LASTEXITCODE # 3: HTML agrupado generado antes del gate
Invoke-Item $salida
```

`--format` admite `json` (predeterminado), `markdown` y `html`. Las opciones preceden a BASE/HEAD. Usar `--output` con un archivo nuevo para guardar UTF-8 sin depender de redirecciones PowerShell; nunca sobrescribe archivos existentes. `--fail-on none` devuelve 0 con el mismo informe, conservando los errores operativos.

| Código | Significado |
| --- | --- |
| 0 | Ayuda/versión o informe que supera la política |
| 1 | Error operativo: entrada, motor, renderizado o escritura |
| 2 | Argumentos inválidos |
| 3 | Informe generado; política no superada |

`examples/breaking/` contiene tres pares `parameter`, `body` y `response` para las nuevas explicaciones. `examples/reports/grouped.html` y `.md` muestran nueve eventos sintéticos en cuatro grupos; sus fuentes `file:///synthetic/` son ilustrativas, no archivos incluidos.

## Límites y licencia

- CLI y esquema **experimentales**, sin garantía de estabilidad ni adecuación a todos los contratos.
- Regresión 3.0.3 y cinco pares concretos 3.1.0; no se verifica cobertura completa 3.1, uniones generales `oneOf`/`anyOf`, OpenAPI 3.2, ARM64, Linux ni macOS.
- Cero hallazgos no significa contratos idénticos. Se conserva la clasificación del motor y el fallback; no se deduce comportamiento real de servidores.
- Motor exactamente 1.39.0; referencias externas y entradas URL/UNC deshabilitadas; comparación limitada a 30 segundos. HTML offline, CSP y escape contextual, sin JavaScript ni recursos externos.
- Los informes reales pueden contener datos de contratos y rutas locales; revisar antes de compartir. La aplicación no los sube automáticamente.
- Proyecto **Apache-2.0**, con NOTICE conservado. Runtime/biblioteca estándar Go **BSD-3-Clause** y texto íntegro en THIRD_PARTY_NOTICES. Sin módulos externos enlazados. oasdiff **Apache-2.0** se obtiene por separado y no se redistribuye en el ZIP.

La evidencia concreta del SHA candidato, reproducibilidad desde dos carpetas, smoke del ejecutable exacto extraído y CI se registra en la PR antes de solicitar aprobación. Los hashes previos de auditoría de un binario v0.1.0 no identifican estos bytes.
